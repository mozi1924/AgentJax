**现状评估**
- Settings UI 已经从“字段渲染 + 少量 custom field”扩展为 SchemaRenderer。`field/group/collection` 继续兼容配置表单，`layout/split/tabs/toolbar/list/detail/collapsible` 等 UI 节点负责更复杂的设置界面。
- Tools Manager 的界面结构现在由 `src-tauri/src/config/settings_ui_sections/tools.json` 声明，前端不再有独立的 Tools Manager 设置组件。剩余的 Tools Manager 前端代码是 `toolManager` data provider 和其数据适配模块，用于加载快照、维护选择状态和执行 policy 保存。
- Data provider 已经按 namespace 注册和路由：`toolManager.*` 由 Tool Manager provider 处理，`plugin.*` 由通用插件 settings provider 处理。SchemaRenderer 本身不再包含 Tools Manager 业务分支。
- 全局设置搜索由 Settings Modal 统一拥有，并传入 SchemaRenderer/data providers。动态 data-source surface 在搜索时保留可见，具体行级筛选由 provider 负责。
- 通用控件能力已经覆盖 switch、segmented、select、button、search、properties、detail items、collapsible，并支持 data-source item 级 `visibleWhen`/`disabledWhen`。这些 data-source 控件的视觉实现集中在 `src/components/settings/schemaRenderer/dataSources/ui.tsx`，避免每个复杂设置界面重复定义按钮、开关、badge 和搜索框样式。
- 插件 manifest 可声明 `settingsSections` 和 `settingsData`，后端会合并设置 section 并暴露 manifest-backed `plugin.*` 数据源，适合插件不写独立 React UI 的普通设置面板。
- 仍需持续关注的边界：更复杂的插件交互目前需要新增 provider action 约定；SchemaRenderer 的 data-source 布局还没有抽成更细的视觉组件；真实 Tauri WebView 下的交互截图验证仍需要可用浏览器自动化环境。
