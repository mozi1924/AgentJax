**现状评估**
- Schema 类型很窄：[src/features/settings/types.ts](/Volumes/Data/AgentJax/src/features/settings/types.ts:14) 只支持 `switch/select/text/textarea/number/secret/tags/key_value/json/prompt_assembler/tool_manager`，没有布局、密度、徽章、表格、分栏、动作区、搜索区、详情面板、可折叠区域、状态展示等 UI 语义。
- 通用渲染集中在一个大组件：[src/components/settings/renderer/FieldRow.tsx](/Volumes/Data/AgentJax/src/components/settings/renderer/FieldRow.tsx:81)。它同时处理 label、校验、draft、保存、控件渲染、key-value 特例、dotenv 导入，后续加复杂控件会继续膨胀。
- 自定义渲染入口是硬编码的：[src/components/settings/renderer/customFields.tsx](/Volumes/Data/AgentJax/src/components/settings/renderer/customFields.tsx:8)。`tool_manager` 基本完全脱离 schema 渲染器。
- Tool Manager 本体是单体组件：[src/components/settings/renderer/ToolManagerField.tsx](/Volumes/Data/AgentJax/src/components/settings/renderer/ToolManagerField.tsx:79)。它自己加载快照、筛选、保存 policy、布局、状态提示、MCP discover，导致它不能复用 SettingsModal 的 `onSaveField/savingPath/fieldErrors` 流程。
- 后端 Tool Manager 只给 summary：[src-tauri/src/tools/catalog/manager_snapshot.rs](/Volumes/Data/AgentJax/src-tauri/src/tools/catalog/manager_snapshot.rs:59)。`ToolSchemaSummary` 只有参数数、required、properties；没有完整参数 schema、参数类型、默认值、enum、嵌套结构，所以前端也无法做真正的 schema 展示。
- 明确的 UI 风险点：Tool Manager 使用固定 `grid-cols-[240px_1fr]`、固定 `h-[360px]` 和 `h-[305px]`：[ToolManagerField.tsx](/Volumes/Data/AgentJax/src/components/settings/renderer/ToolManagerField.tsx:272)。这很容易在设置弹窗较窄、搜索/按钮较多、长名称/多语言文本时溢出或挤压。
- 还有一个实际保存风险：`key_value` 输入在 `onChange` 后紧接 `onBlur` 时用的是闭包里的旧 `keyValueEntries`：[FieldRow.tsx](/Volumes/Data/AgentJax/src/components/settings/renderer/FieldRow.tsx:421)，React state 异步时可能保存上一版值。
